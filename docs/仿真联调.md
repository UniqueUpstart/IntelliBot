# 仿真联调说明

当前项目只通过 MuJoCo 模拟机器人，不连接 ROS 2、真机或任何外部设备。

## 链路

```text
浏览器 frontend/            backend (C++17, :8080)        mujoco_bridge.py (:8090)
Advance 弹窗  ── /api/v1/... ──▶ 校验 + 转发 ── /cmd/* ──▶  MjModel / MjData
              ◀── /api/v1/sim/{state,frame} ◀── 透传 ◀──  100 Hz 循环 + JPEG
```

前端只使用相对路径 `/api/v1`，同源由后端托管 `frontend/`，入口是
`http://127.0.0.1:8080/ui/IntelliBot.html`。

## 启动与关闭

两个终端，均在项目根目录执行。

```powershell
# 终端 1：仿真桥 :8090
.venv\Scripts\python.exe sim\mujoco_bridge.py --port 8090 --headless

# 终端 2：后端 :8080
.\backend-build\intellibot_backend.exe --port 8080 --web-root frontend --sim-url http://127.0.0.1:8090
```

关闭时两个终端各按一次 `Ctrl+C`，先关后端再关仿真桥。端口确认：

```powershell
Get-NetTCPConnection -State Listen -LocalPort 8080,8090
```

## 当前界面能做什么

| 界面操作 | 接口与结果 |
|---|---|
| Advance → 连接仿真 | POST /api/v1/connections `{"mode":"sim"}`，转发桥 /health |
| 断开 | DELETE /api/v1/connection，同时给桥发一次停止 |
| 关节滑块、预设姿态、手势、步态、速度 | POST /api/v1/control/* 与 /api/v1/sim/*，桥真的修改 qpos |
| 画面 | GET /api/v1/sim/frame，返回桥的 JPEG |
| 状态与电量占位 | GET /api/v1/sim/state、GET /api/v1/status |
| 日志 | GET /api/v1/logs，来自后端内存 |

`mode` 只接受 `sim`（MuJoCo 桥）与 `mock`（纯内存模拟，用于接口自测）。
不存在真机 / ROS 2 模式，也没有机型列表接口。

## 已移除的硬件连接

- 后端：`ros2_implemented` 字段、`ROS2_NOT_IMPLEMENTED` 分支、`/api/v1/robots` 机型档案、
  `verified_on_robot` 字段。
- 前端：顶栏 Connect 胶囊、机型列表与 Confirm 页脚、`js/models.js`、
  已停用的 `js/integration.js` 与 `css/integration.css`。
- 脚本：`setup_ros_humble.sh`、`verify_ros_local.py`、`build_workspace.sh`。
- 文档：WSL/ROS 2 迁移、真机验证与 SDK 构建相关记录。

## 示例

```powershell
curl http://127.0.0.1:8080/api/v1/health
curl -X POST http://127.0.0.1:8080/api/v1/connections -H 'Content-Type: application/json' -H 'Idempotency-Key: sim-1' -d '{"mode":"sim"}'
curl http://127.0.0.1:8080/api/v1/sim/state
curl -X POST http://127.0.0.1:8080/api/v1/sim/preset -H 'Content-Type: application/json' -H 'Idempotency-Key: preset-1' -d '{"name":"tpose"}'
```

写请求都需要 `Idempotency-Key`；同键同内容返回原结果，同键不同内容返回 409。
